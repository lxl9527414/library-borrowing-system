# 面试速查卡（20 问 · 30 秒版）

> 用法：面试前 1 天通读；每题的"关键词"能脱口而出即可。

## A. 项目与架构

**1. 简单介绍这个项目？**
> AI 原生图书借阅系统：Java 业务底座 + Python AI 层 + Vue 前端。AI 能真实操作业务数据（借还预约），写操作必须用户确认；知识问答可溯源、无依据会拒答。已公网部署。

**2. 为什么用双栈？**
> 业务资产在 Java（事务/权限/审计），AI 生态在 Python（LangGraph/embedding）；AI 不直连数据库，通过内部 HTTP 工具接口复用 Java 的业务规则。

**3. 一次对话的数据流？**
> 浏览器 → nginx → FastAPI（从 token 解析身份）→ LangGraph 调模型 → 工具调 Java 内部接口 → 结果回灌模型 → SSE 流式返回。

**4. 安全边界怎么做的？**
> 三层：身份只认 token（模型无法伪造）、内部接口要 X-Internal-Token、nginx 公网封禁内部路径；写操作还要确认。

## B. Agent

**5. Agent 循环怎么控制？**
> 最大步数 8 + 工具白名单 + 参数校验 + 错误回灌；连续失败或超步强制收尾。

**6. 人在回路怎么实现？**
> LangGraph `interrupt()` 暂停并保存确认 payload；前端确认后 `Command(resume=...)` 恢复同一 thread_id；确认状态 Redis TTL 300s、GETDEL 一次性消费。

**7. 怎么防止 AI 乱操作？**
> 三重：身份来自 token、写操作必须确认、工具白名单 + 参数校验；再加内部接口密钥与公网封禁。

**8. 工具调用失败怎么办？**
> 业务失败回灌让模型解释；上游 5xx 提示稍后重试；401 直接透传前端要求重新登录（不让模型圆场）。

**9. 为什么不用 LangChain AgentExecutor？**
> 循环边界、确认中断、审计点不够可控；用 LangGraph 自建状态机，节点职责清晰。

## C. RAG

**10. RAG 链路？**
> 535 块语料（图书/规则/FAQ）→ 1024 维 embedding → 向量与 BM25 各 Top20 → RRF 融合 → gte-rerank（20→5）→ 带 citation_no 的 chunks → 强制 [n] 引用 → 无依据拒答。

**11. 为什么混合检索？**
> 向量擅长同义，BM25 擅长精确词（书名/ISBN/金额）；规则类问题 BM25 被同形 FAQ 抢位（MRR 0.394），向量救回 0.578。

**12. 重排为什么没让指标更好？**
> 原先只给 top5 候选，捞不回后面的正确块；改 20 候选后 BM25 变好，但仍低于纯向量——原因是评测口径把 rule 源当唯一正解，而 reranker 按语义把等价 FAQ 排前；另有 8% 调用失败回退。我把它写成已知局限，没有为刷分调参。

**13. 怎么防幻觉？**
> 提示词先检索 + 低分过滤（0.67）+ 空结果拒答 + 评测里 10 条无依据问题（拒答 9/10，0 编造）。

## D. 评测

**14. 怎么证明 RAG 有效？**
> 两层：检索 Recall@5 1.000 / MRR 0.916；答案 faithfulness 0.940、引用准确率 0.913、拒答 9/10。85 条评测集，脚本可复现。

**15. 为什么自研 RAGAS？**
> 依赖装不上（tiktoken 需联网下 BPE），按指标定义自研，更可控更便宜；局限（judge 同源）如实写进报告。

**16. 改一版 Prompt 怎么验证？**
> 同一评测集重跑，对比 faithfulness / 引用准确率 / 拒答率；检索看 Recall 是否守住 CI 门禁（≥0.95）。

## E. 成本与工程

**17. 单轮成本？怎么降？**
> ≈¥0.0094/轮；96% 成本在输入（4054 in / 165 out）。降本靠截断工具结果、控制 top-k、会话摘要、语义缓存、Prompt 精简，每个都要评测验证。

**18. 测试怎么离线跑？**
> mock LLM + fakeredis + httpx.MockTransport；319 AI 单测 + 71 后端单测全离线，CI 不需要 Key。

**19. 线上怎么排障？**
> 结构化日志按 traceId 串起请求/模型/工具/错误码；Langfuse 看 span 时间线；有降级与回滚。

**20. 部署踩过最大的坑？**
> CentOS 7 glibc 2.17：Miniconda 只能用 24.x；numpy 锁 <2；tiktoken 锁 0.8.0；加 swap 与内存上限防 OOM。

## F. 陷阱题（一定要准备好）

**21. Python 水平怎么样？**
> 能读能改：服务是我主导设计的，Python 用 AI 辅助实现，我负责架构、Prompt、契约和验收；能定位到文件改 bug。

**22. 数据量这么小，有意义吗？**
> 规模是 demo 级（535 块/500 本书），但工程闭环是真的：评测、门禁、降级、部署都按生产标准做；扩量是工程问题，不是能力问题。

**23. 为什么不用 Dify/Coze？**
> 拖拽平台体现不了权限透传、事务一致性、评测闭环；写代码是为了证明"知道每一步为什么"。

**24. 项目里你独立做了哪些？**
> 架构与接口契约、Prompt 与评测口径、人在回路设计、部署运维；Python 实现由 AI 辅助完成，我负责读懂、修改与验收。
