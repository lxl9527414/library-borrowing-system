# 学习路线与 14 天计划

> 目标：14 天内达到「能读懂本项目 Python 代码 + 能讲清楚每个技术决策 + 能改一个小功能」。
> 每天 2–3 小时，周末可加倍。**不要求学完 Python，只要求过关 6 个主题。**

## 一、学习顺序（为什么是这个顺序）

```
Prompt 工程（1 天）
      ↓
RAG 全链路（2 天）── 需要先懂 Prompt 才能懂"强制引用/拒答"
      ↓
Agent 与工具调用（2 天）── 依赖工具返回，RAG 是其中一个工具
      ↓
评测体系（1.5 天）── 前面所有东西都要用指标证明
      ↓
成本与延迟（1 天）── 有了指标才知道优化什么
      ↓
工程化与质量（1.5 天）── 把上面所有东西变成可交付的系统
```

## 三、每天的最小产出

每天结束前写下 3 行（放进自己的笔记）：
1. 今天学到的**一个概念**（用自己的话）；
2. 对应的**一个文件/一次实验**；
3. 还**没搞懂的一个问题**（第二天先解决它）。

## 四、不要求掌握的内容（可跳过）

- Python 元类、GIL、C 扩展、asyncio 事件循环底层实现；
- LangGraph 源码、BM25 数学推导；
- 模型训练 / 微调 / 分布式推理。

> 面试不会问这些；把时间花在"能讲清系统为什么这么设计"上。
