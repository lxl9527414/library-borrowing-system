# 云阁图书管理系统技术说明

> 更新日期：2026-11-03（已包含 AI 应用层）  
> 线上地址：<https://lxlssr.icu>  
> 项目形态：**Java 业务底座 + Python AI 层 + Vue 前端** 的双栈系统，三个独立进程通过 HTTP 通信。

## 1. 项目概述

### 1.1 业务能力（原有系统）

面向小型图书馆 / 图书角的在线借阅系统：图书管理、借阅与归还、逾期罚金、预约排队、动态借阅规则、用户与权限、操作审计、工作台统计。

### 1.2 AI 能力（新增）

在业务系统之上新增「智能馆员」：

- **查馆藏 / 查借阅**：调用业务工具查询真实库存与在借记录；
- **借书 / 还书 / 预约**：AI 可**真实写库**，但写操作必须经用户确认（人在回路）；
- **知识问答**：基于 535 块语料的 RAG，回答规则/罚金/预约问题，**正文带 `[n]` 引用**，无依据时**强制拒答**；
- **安全边界**：AI 不直连数据库，身份只从 token 解析，内部接口有独立密钥且公网封禁。

| 测试 | 后端 71 个 + AI 服务 319 个（全离线） |

## 3. 整体架构

```text
用户浏览器
    ↓ HTTPS
Cloudflare
    ↓ HTTP
Nginx :80
    ├── /                 → Spring Boot :18080 ──┬── MySQL 8 :3306（仅本机）
    │                                            └── Redis 7 :6379（仅本机）
    └── /api/ai/**        → FastAPI :8000（仅本机）
                              └── /api/ai/internal/** → Spring Boot :18080
                                  （Authorization: Bearer <用户token> + X-Internal-Token）
```

### 3.1 一次对话的数据流

1. 浏览器 `POST /api/ai/chat`（`Authorization: Bearer <token>`）；
2. Nginx 转发到 FastAPI；FastAPI 从 token 解析身份（**不信任 body 中的 userId**）；
3. LangGraph 调模型 → 模型请求工具 → 工具执行器调 Java 内部接口；
4. Java 校验内部密钥 + 用户 token → 读写 MySQL → 返回 JSON；
5. Python 将结果回灌模型 → 生成带 `[n]` 引用的回答；
6. 若模型请求写工具 → `interrupt` 暂停 → 前端确认 → `resume` → 再调 Java 写接口；
7. SSE 流式返回：`meta → token... → tool_call/tool_result → done`。

### 3.2 三层安全边界

| 层 | 机制 | 防什么 |
|---|---|---|
| 身份 | 只从 `Authorization` token 解析用户 | 模型/客户端伪造 userId |
| 服务间 | `X-Internal-Token` 共享密钥 | 外部直接调用内部接口 |
| 网络 | Nginx 对 `/api/ai/internal/` 返回 404 | 公网访问内部路径 |

## 5. 数据库与 Redis

### 5.1 数据表（6 张）

| 表名 | 作用 |
|---|---|
| `sys_user` | 用户、角色（ADMIN/READER）、状态 |
| `book` | 图书、分类、价格、库存 |
| `borrow_record` | 借阅、归还、逾期、续借次数、罚金 |
| `borrow_rule` | 借阅规则单行配置（上限/借期/续借/罚金/预约保留） |
| `book_reservation` | 预约排队与到书保留状态 |
| `operation_log` | 关键操作审计日志（保留 90 天） |

关键约束：

- `book_reservation.active_key` 是**生成列 + 唯一索引**，从数据库层拦截重复预约；
- 库存扣减用**条件更新**（`WHERE available_stock > 0`），避免并发超卖；
- 归还回补使用 `LEAST(available_stock + 1, total_stock)`，避免库存超过总数。

### 5.2 Redis 键设计

| 键 | 用途 | TTL |
|---|---|---|
| `library:token:<token>` | 登录会话（UserSession JSON） | 7 天（可配置） |
| `ai:session:<sessionId>` | AI 对话历史 | 1 小时 |
| `ai:confirmation:<id>` | 待确认的写操作（GETDEL 一次性消费） | 300 秒 |

> AI 服务使用 Redis `db=1`，与业务登录态隔离。

## 6. 核心业务流程

### 6.1 登录与权限

```text
前端提交账号密码 → BCrypt 校验 → 生成随机 Token → 用户信息写 Redis（7 天）→ 返回 Token
请求携带 Authorization: Bearer <token> → AuthInterceptor 查 Redis → 校验 @RequireRole → 放行
```

### 6.2 借书与还书

```text
借书：检查规则（上限/重复/状态）→ 条件更新库存 → 插入 borrow_record（同一事务）
还书：校验记录状态 → 计算罚金 → 置 RETURNED → LEAST 回补库存 → 若有预约则提升队首
```

### 6.3 预约状态机

```text
WAITING（库存为 0 才可预约）
   ├── 取消 → CANCELED
   └── 图书归还且轮到时 → READY（写保留截止时间）
          ├── 读者取书 → COMPLETED
          └── 超时未取（定时任务每小时）→ EXPIRED → 自动提升下一位
```

### 6.4 罚金规则

```text
罚金 = min(逾期天数 × 每日罚金, 罚金上限)   # 归还时按天数差向上取整计算
状态：NONE → UNPAID → PAID（管理员确认缴纳）
```

罚金未结清时禁止继续借书/续借。

### 6.5 审计与规则配置

- `@Auditable(module, action)` + AOP 记录操作人、IP、参数（密码脱敏）、结果、耗时；
- 借阅规则集中在 `borrow_rule` 单行表，`BorrowRuleService.current()` 统一读取，改规则无需发版；
- 持久层分工：单表 CRUD 走 `BaseMapper` / `LambdaQueryWrapper`，跨表动态 SQL 走 Mapper XML（只有借阅记录分页、预约分页两类）。

## 8. AI 应用层

### 8.1 七个工具

| 工具 | 读/写 | 说明 |
|---|---|---|
| `search_books` | 读 | 按书名/作者/分类检索馆藏 |
| `get_book_detail` | 读 | 单本详情 + 预约队列 |
| `get_my_borrows` | 读 | 当前用户在借记录 |
| `search_knowledge` | 读 | RAG 检索（规则/FAQ/图书） |
| `borrow_book` | **写** | 借书（必须确认） |
| `return_book` | **写** | 还书（必须确认） |
| `reserve_book` | **写** | 预约（必须确认） |

工具返回统一结构：`{ok, data/error, message?, citation_no?}`。

### 8.2 Agent 状态机与人在回路

```text
agent（调模型）→ 只读工具 → tools → 回到 agent（最多 8 步）
              → 写工具   → authorize（构造确认卡）→ interrupt 暂停
                                                    ↓ 用户确认（/chat/confirm）
                                              resume → tools 执行 → agent
```

- 确认状态存 Redis（TTL 300s、GETDEL 一次性消费，防重放）；
- `interrupt` 恢复会重放当前节点，因此 `authorize` 必须是无副作用的纯计算；
- 真实模型跨轮只传 `bookId` 时，确认前回查图书详情补书名，避免确认卡出现《该图书》。

### 8.3 RAG 链路

```text
535 块语料 → 1024 维 embedding → 向量 Top20 + BM25 Top20 → RRF(k=60) 融合
→ gte-rerank（可选，20 候选）→ 带 citation_no 的 chunks → 强制引用 / 无依据拒答
```

检索结论：向量单独最优（Recall@5 **1.000**、MRR **0.916**），因此生产默认 `vector`、重排关闭；详细六档对比见 [RAG评测报告.md](RAG评测报告.md)。

### 8.4 评测

- 85 条评测集（图书 30 / FAQ 30 / 规则 15 / 无依据 10）；
- 检索层：Recall@5、MRR（CI 门禁 ≥ 0.95）；
- 答案层：faithfulness **0.940**、answer_relevancy 0.971、context_precision 0.667、引用准确率 **0.913**、拒答 9/10；
- 自研 RAGAS 等价指标 + LLM-as-judge（DeepSeek `json_object`），支持重试与断点合并。

### 8.5 可观测与扩展

- 结构化 JSON 日志（traceId / sessionId / tool / durationMs / code）；
- Langfuse ingestion 协议埋点（工具/生成/错误 span，熔断 + 采样，默认 Noop）；
- 7 个工具封装为 **MCP Server**（写操作用 `confirm` 两段式），可被任意 Agent 客户端复用。

### 8.6 降级矩阵

| 依赖 | 降级 |
|---|---|
| 向量检索 | → BM25 |
| 重排 | → 原顺序 |
| Redis | → 进程内存（health 暴露状态） |
| checkpointer | → InMemorySaver |
| 模型 | 重试 1 次；已吐 token 不重试 |
| 整个 AI 服务 | 业务不受影响（两个进程） |

## 13. 已知限制（如实列出）

1. **向量库**：生产用 NumPy 内存索引（535 块）足够，pgvector 后端已实现但未启用；
2. **checkpointer**：未安装 `langgraph-checkpoint-redis`，图执行进度不跨重启（会话历史在 Redis，不受影响）；
3. **Langfuse**：代码接入完成并有离线测试，但未在真实环境跑出看板；
4. **重排**：评测未超过纯向量，默认关闭；
5. **覆盖率**：Controller / 配置类未覆盖，靠 e2e 与手工验证兜底；
6. **生产内存**：2C1.76G 混部，容量有限（只读接口约 100 QPS）；
7. **AI 页面**：依赖 AI 服务，停掉后对话页显示"未连接"（业务功能不受影响）。
