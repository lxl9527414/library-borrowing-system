## 1. 项目一句话

## 2. 简历 bullets（4 条，按岗位侧重选 3 条）

> **AI 原生图书借阅系统**（Java + Python 双栈）｜ Spring Boot 3.5 · Spring AI 生态替代方案 · LangGraph · RAG · Vue 3
>
> - **Agent 工程**：用 LangGraph 实现「agent → 授权 → 工具 → agent」状态机，把借书/还书/预约等 7 个业务能力工具化；写操作经 `interrupt` 暂停、前端确认卡批准后才执行，杜绝模型误操作（E2E 16 项断言覆盖身份透传/确认/落库，`scripts/e2e_ai.py`）
> - **RAG 全链路**：自建 535 块知识语料 → 通义 text-embedding-v3（1024 维）向量索引 → BM25+向量混合检索 → gte-rerank 重排；向量检索使规则类 MRR 从 0.394 提升到 0.578，Recall@5 达 1.000（`docs/RAG评测报告.md`）
> - **答案质量与评测**：实现引用溯源（正文 `[n]` → 来源卡）与无依据拒答；自建 85 条评测集 + RAGAS 等价指标（LLM-as-judge），faithfulness **0.940**、引用准确率 **0.913**、拒答 9/10（`docs/RAG评测报告.md` §13）
> - **工程与成本**：312 个 AI 服务单测 + 71 个后端单测全离线可跑，GitHub Actions 四 job 门禁（含 RAG 召回阈值）；实测 TTFT P50 **897 ms**、单轮成本 **≈¥0.0094**，定位到"成本 96% 在输入"并给出降本路径（`docs/AI性能与成本报告.md`）

**技术关键词**（投递系统/HR 筛选用）：LangGraph、Agent、Function Calling、RAG、向量检索、pgvector、Embedding、Rerank、Prompt Engineering、SSE 流式、LLM-as-judge、RAGAS、FastAPI、Spring Boot、Redis、Docker、CI/CD

## 3. 30 秒口述版（自我介绍里带项目）

> 我的项目是一个图书馆借阅系统，原本是 Spring Boot 的 CRUD 项目。我在它上面加了一层 AI 应用：用 LangGraph 把借书、还书、预约这些真实业务能力做成工具给模型调用，写操作必须用户确认才执行；另外做了一套 RAG 知识问答，能回答借阅规则这类问题并给出引用。为了证明它真的有效，我建了 85 条评测集，检索层和答案层都有数字：向量检索 Recall@5 是 1.0，答案的 faithfulness 是 0.94，引用准确率 0.91。整套东西 312 个单测全离线可跑，CI 也会拦回归。

## 5. STAR 模板（讲项目用）

**S（背景）**：原有系统是标准 Spring Boot + Vue 的图书借阅管理，功能完整但没有 AI 能力，与"AI 应用开发"岗位不匹配。

**T（任务）**：在不破坏原有业务正确性的前提下，加一层真实可用的 AI 能力，并且要有可量化的效果证据，而不是 demo。

**A（行动）**
1. 先定契约：Java 侧新增 8 个内部工具端点（身份只从 token 解析、内部密钥防公网），AI 侧不直连数据库；
2. 用 LangGraph 做编排：只读工具直接调用，写工具进 `interrupt` 等确认；
3. RAG：语料构建 → embedding → 向量/混合检索 → 重排，并做检索层评测；
4. 接入 Agent 后做答案层评测，发现并修复"重排只看到 top-5 候选"等真实缺陷；
5. 工程化：mock 模型让 312 个测试离线可跑、CI 四 job 门禁、SSE 流式与前端确认/引用卡片。

**R（结果）**：检索 Recall@5 1.0、答案 faithfulness 0.94、引用准确率 0.91；TTFT 0.9 s；单轮成本不到 1 分钱；整套可一条命令本地跑起来。

## 6. 容易被追问的点（提前准备）

| 追问 | 回答要点 |
|---|---|
| 为什么不用 Dify/Coze？ | 它们适合快速搭 demo，但体现不了工程能力：权限透传、事务一致性、评测闭环都要自己控制；我这里写代码是为了证明"知道每一步为什么"。 |
| 你的 RAG 效果好不好？ | 给三层数字：检索 Recall@5 1.0、答案 faithfulness 0.94、引用准确率 0.91；并主动说明局限（judge 与生成模型同源、rule/FAQ 多源等价）。 |
| 怎么防止 AI 乱操作？ | 三重：身份来自 token（LLM 无法伪造）、写操作必须确认（interrupt）、工具白名单 + 参数校验；另有内部接口密钥与公网封禁。 |
| 模型挂了怎么办？ | 网关有超时/重试/降级链；降级到备用模型或 mock；检索层向量不可用自动降级 BM25；Redis 不可用降级内存并暴露在 health。 |
| 成本怎么控？ | 实测成本 96% 在输入：工具结果截断、检索 top-k 限制、Agent 最大步数 8；下一步做语义缓存与会话摘要。 |
| 怎么保证不幻觉？ | 强制引用 + 拒答策略（无 chunks 必须拒答）+ 低相关阈值过滤；评测里拒答 9/10、编造 0。 |
| 为什么自研评测而不是 RAGAS 库？ | 依赖装不上（tiktoken 需联网下 BPE），所以按 RAGAS 指标定义自研，成本与可解释性更好；局限也写清楚了。 |
| 你遇到最大的坑？ | ① 生产构建下 `/chat` 404（SpaController 白名单硬编码，Vite dev 有 fallback 发现不了）；② 重排只看到 top-5 候选导致"重排反而更差"；③ 真实模型跨轮只传 bookId，确认卡显示《该图书》。三个都写进了文档。 |
