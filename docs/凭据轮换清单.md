## 2. 轮换步骤（以管理员密码为例）

```bash
# ① 生成本地 bcrypt 哈希（不要用明文存库）
#    项目已有 spring-security-crypto，可用任意 JDK 环境跑一段小脚本，或用 Python bcrypt：
python3 -c "import bcrypt;print(bcrypt.hashpw(b'你的新密码', bcrypt.gensalt(rounds=10, prefix=b'2b')).decode())"
# → $2b$10$....

# ② 更新线上数据库（示例：服务器上执行，密码从环境变量读，不要写进命令历史）
mysql -uroot -p"${MYSQL_ROOT_PASSWORD}" library_db \
  -e "UPDATE sys_user SET password='${NEW_HASH}' WHERE username='admin';"

# ③ 更新部署环境文件
sudo vi /opt/library/config/library.env     # DB_PASSWORD / REDIS_PASSWORD / AI_INTERNAL_TOKEN
sudo systemctl restart library-server

# ④ 更新本地开发环境（.env，gitignored）
#    DEMO_USER / DEMO_PASSWORD / AI_INTERNAL_TOKEN ...
bash scripts/dev_down.sh && bash scripts/dev_up.sh

# ⑤ 更新凭据备忘（本地文件，gitignored）
#    cp deploy/credentials.local.example deploy/credentials.local 然后填入新值
#    确认：git check-ignore deploy/credentials.local  有输出即被忽略
```

**其他账号**：MySQL/Redis 需要用各自的方式改（`ALTER USER ... IDENTIFIED BY`、`redis-cli CONFIG SET requirepass`），
改完都要同步 `library.env` 与 `deploy/conf/*`。

## 6. 可复制执行的命令（服务器侧）

> 前提：能 SSH 到 ECS，且有 sudo。**建议先把这段整体看一遍再执行**；每步都可单独回滚（第 0 步有备份）。

### 第 0 步：备份与现状记录（必做）

```bash
sudo cp /opt/library/config/library.env /opt/library/config/library.env.bak.$(date +%Y%m%d%H%M)
sudo cp /etc/redis/redis.conf /etc/redis/redis.conf.bak.$(date +%Y%m%d%H%M) 2>/dev/null || true
sudo grep -E "^(DB_PASSWORD|REDIS_PASSWORD|AI_INTERNAL_TOKEN)" /opt/library/config/library.env | sed 's/=.*/=<有值>/'
```

### 第 1 步：生成 bcrypt 哈希（admin / reader 用）

在服务器上执行（**不要用明文密码**，从 stdin 读）：

```bash
# 仓库里有这个工具（也可拷到服务器）
read -rs NEW_ADMIN_PW && echo
ADMIN_HASH=$(printf '%s' "$NEW_ADMIN_PW" | bash scripts/gen_bcrypt_hash.sh | tail -1)
echo "$ADMIN_HASH" | head -c 7    # 应看到 $2a$ / $2b$ / $2y$

read -rs NEW_READER_PW && echo
READER_HASH=$(printf '%s' "$NEW_READER_PW" | bash scripts/gen_bcrypt_hash.sh | tail -1)
```

> 若服务器没有 `htpasswd` 也没有 python bcrypt：`sudo yum install -y httpd-tools`（CentOS）。

### 第 2 步：改应用账号（管理员 / 读者）

```bash
mysql -uroot -p"$MYSQL_ROOT_OLD_PW" library_db <<SQL
UPDATE sys_user SET password='${ADMIN_HASH}'  WHERE username='admin';
UPDATE sys_user SET password='${READER_HASH}' WHERE username IN ('reader','reader2','reader3','reader4','reader5');
SQL
```

### 第 3 步：改 MySQL 密码

```bash
# 应用账号
mysql -uroot -p"$MYSQL_ROOT_OLD_PW" <<SQL
ALTER USER 'library_app'@'localhost' IDENTIFIED BY '${NEW_MYSQL_APP_PW}';
SQL
# root（改完立刻用新密码验证，避免自己锁在外面）
mysql -uroot -p"$MYSQL_ROOT_OLD_PW" -e "ALTER USER 'root'@'localhost' IDENTIFIED BY '${NEW_MYSQL_ROOT_PW}';"
mysql -uroot -p"$NEW_MYSQL_ROOT_PW" -e "SELECT 1;"
```

### 第 4 步：改 Redis 密码

```bash
redis-cli -a "$REDIS_OLD_PW" CONFIG SET requirepass "$NEW_REDIS_PW"
redis-cli -a "$REDIS_OLD_PW" CONFIG REWRITE        # 写入配置文件，重启后仍生效
redis-cli -a "$NEW_REDIS_PW" PING                  # 应返回 PONG
```

### 第 5 步：更新应用环境文件并重启

```bash
sudo sed -i "s|^DB_PASSWORD=.*|DB_PASSWORD=${NEW_MYSQL_APP_PW}|" /opt/library/config/library.env
sudo sed -i "s|^REDIS_PASSWORD=.*|REDIS_PASSWORD=${NEW_REDIS_PW}|" /opt/library/config/library.env
# 如果 AI 服务也部署在服务器上，同时轮换内部密钥（两端必须一致）
sudo sed -i "s|^AI_INTERNAL_TOKEN=.*|AI_INTERNAL_TOKEN=${NEW_AI_INTERNAL_TOKEN}|" /opt/library/config/library.env

sudo systemctl restart mysql redis-library library-server
# 若 AI 服务也在服务器上：
sudo systemctl restart library-ai 2>/dev/null || true
```

### 第 6 步：验证（逐项打勾）

```bash
# 1) 站点登录（新管理员密码）
curl -s -X POST http://127.0.0.1:18080/api/auth/login \
  -H 'Content-Type: application/json' -d '{"username":"admin","password":"'"$NEW_ADMIN_PW"'"}' | head -c 80

# 2) 业务接口可用
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:18080/api/books

# 3) AI 服务与工具链（内部 token 两端一致才通）
curl -s http://127.0.0.1:8000/api/ai/health
```

### 第 7 步：轮换模型 API Key（只能你本人做）

1. **通义 DashScope**：登录阿里云百炼控制台 → API-KEY 管理 → **删除旧 Key** → 创建新 Key
2. **DeepSeek**：登录 platform.deepseek.com → API Keys → 删除旧 Key → 创建新 Key
3. 新 Key 写入**服务器与本地**的 `.env`（不要贴到聊天/群/文档里）：
   ```bash
   # 本地
   vi .env      # DASHSCOPE_API_KEY=... / DEEPSEEK_API_KEY=...
   bash scripts/dev_down.sh && bash scripts/dev_up.sh
   ai-service/.venv/bin/python scripts/check_llm.py    # 自检连通性/function calling/TTFT
   ```

### 第 8 步：收尾（降低"再泄露"的概率）

# 2) 清掉可能含密码的 shell 历史（谨慎：会清空当前会话历史）
