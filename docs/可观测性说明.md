# 可观测性说明（Langfuse 接入）

> 目标：把"一次用户对话到底发生了什么"变成可回放的 trace —— 模型调用、工具调用、检索、token 成本、延迟。
> 状态：**代码已接入并测试通过；本机未做真机验证**（Docker 拉 Langfuse 镜像受网络限制），如实说明见 §5。

---

## 1. 为什么不直接用官方 SDK

- Langfuse SDK v3/v4 的 API 变化较大（`trace/span` → `observation`），升级容易踩坑；
- 我们只需要"上报 trace/span/generation"这一个能力，而 **ingestion HTTP 协议**是稳定契约：
  `POST /api/public/ingestion` + Basic Auth + `{"batch": [...]}`；
- 用 `httpx` 直接发，零新依赖、可用 `MockTransport` 完全离线测试。

实现：`ai-service/app/obs/langfuse_tracer.py`

---

## 2. 埋点位置（业务代码零侵入）

所有 SSE 事件都经过 `RunContext.emit()`（`ai-service/app/agent/state.py`），在这里把事件翻译成 Langfuse 事件：

| Agent 事件 | 转成什么 | 关键字段 |
|---|---|---|
| `tool_call` | 记录开始时间 | callId / name / args |
| `tool_result` | `SPAN`（name=`tool:xxx`） | ok / summary / **durationMs** |
| `done` | `GENERATION`（usage）+ 关闭 trace | promptTokens / completionTokens / latencyMs |
| `error` | 关闭 trace（level=ERROR） | code / message |

一个用户回合 = 一个 trace（id 复用 `traceId`）+ 若干 span/generation，在 `done`/`error` 时**一次性批量上报**。

## 3. 怎么启用

```bash
# 1) 启动 Langfuse（仅 Postgres，v2 不需要 ClickHouse）
docker compose exec pgvector psql -U library -d library_ai -c "CREATE DATABASE langfuse;"
docker compose --profile observability up -d langfuse

# 2) 打开 http://127.0.0.1:3000 → 注册 → 创建 project → 复制 public/secret key

# 3) 写 .env
LANGFUSE_ENABLED=true
LANGFUSE_HOST=http://127.0.0.1:3000
LANGFUSE_PUBLIC_KEY=pk-lf-xxx
LANGFUSE_SECRET_KEY=sk-lf-xxx

# 4) 重启 AI 服务
bash scripts/dev_down.sh && bash scripts/dev_up.sh

# 5) 在对话页问几个问题，然后回 Langfuse 看 Trace
```

## 4. 兜底行为（重要）

| 场景 | 行为 |
|---|---|
| `LANGFUSE_ENABLED=false` 或 Key 缺失 | 使用 `NoopTracer`，**零网络请求、零开销** |
| Langfuse 未启动 / 网络失败 / 返回 5xx | 只 log.warn 一次，**自动熔断**后续不再上报，主链路不受影响 |
| 采样率 `LANGFUSE_SAMPLE_RATE=0.0` | 完全不上报（生产可设 0.1 控制量） |
| 事件字段缺失/格式异常 | 静默跳过，不抛异常 |

对应测试：`ai-service/tests/test_langfuse_tracer.py`（7 个离线用例，覆盖 Noop、batch 上报、Basic Auth、
usage 映射、500 熔断、采样率 0、异常 payload）。

## 5. 为什么本机没做真机验证（如实说明）

- 本机 Docker Hub 被墙，Langfuse 镜像拉取失败（`Keychain Error` / 无法访问 registry）；
- Langfuse 还依赖 Postgres（v2）；本机 Postgres 未安装、pgvector 镜像同样拉不下来；
- 因此交付的是**代码 + 配置 + 离线测试**，`docker-compose.yml` 里已加 `observability` profile 与启用步骤；
  在有网络的环境按 §3 操作即可，无需改代码。

**面试表述建议**："Langfuse 我按 ingestion 协议接好了，trace/span/generation 和成本都能上报，做了熔断与采样；
本机网络受限没能起服务，所以没有截图，但上报协议有离线测试覆盖。"

## 6. 与现有日志的关系

`app/obs/logging.py` 的结构化 JSON 日志字段（traceId/sessionId/tool/durationMs/code）与 Langfuse trace 字段**同名对齐**，
方便用 grep/Loki 排查线上问题，也能和 Langfuse 的 trace 互相印证（同一个 traceId 两边都能搜到）。
